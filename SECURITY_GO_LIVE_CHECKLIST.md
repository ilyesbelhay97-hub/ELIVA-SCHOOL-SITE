# ELIVA SCHOOL — Security Go-Live Checklist

## Environment and secrets

- [ ] Set `NEXT_PUBLIC_SITE_URL` to the final HTTPS domain.
- [ ] Set `NEXT_PUBLIC_SUPABASE_URL` in Vercel.
- [ ] Set `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` in Vercel.
- [ ] Set `SUPABASE_SERVICE_ROLE_KEY` in Vercel Production and Preview as a server-only secret.
- [ ] Set `ADMIN_EMAILS` to the approved admin addresses.
- [ ] Set `NEXT_PUBLIC_WHATSAPP_URL` if the public WhatsApp CTA is used.
- [ ] Confirm `.env.local` and all secret files are ignored by Git.
- [ ] Search the deployed source/build configuration for `service_role`; it must not appear in client bundles.

## Supabase schema and RLS

- [ ] Confirm `registrations`, `admission_attempts`, `admission_events`, `admission_documents` and `admission_payments` have RLS enabled.
- [ ] Confirm `courses`, `trainers_crm`, `trainer_interactions`, `centers` and `center_interactions` have RLS enabled.
- [ ] Confirm anonymous users can only INSERT validated registrations.
- [ ] Confirm anonymous users cannot SELECT, UPDATE or DELETE CRM, admission or payment rows.
- [ ] Confirm `public_trainers_cms` is `security_invoker` and exposes only public columns.
- [ ] Confirm only the approved admin email or `app_metadata.role=admin` can pass admin policies.
- [ ] Confirm the legacy `status`/CMS `publish_status` publication policy is standardized.

## Storage

- [ ] Confirm `trainer-cv` is private, PDF-only and limited to 5 MB.
- [ ] Confirm `payment-receipts` is private, image-only and limited to 5 MB.
- [ ] Confirm `course-covers` and `trainer-public` are public-read only if their media is approved for publication.
- [ ] Confirm public users cannot list or download CVs or payment receipts.
- [ ] Confirm CV and receipt links are short-lived signed URLs generated by protected server routes.
- [ ] Confirm failed database inserts remove uploaded orphan files.

## Authentication and admin authorization

- [ ] Anonymous visit to `/admin` redirects to `/admin/login`.
- [ ] Authenticated non-admin user is rejected by both protected pages and every admin API route.
- [ ] The approved admin email can log in and access the CRM.
- [ ] Logout clears the session and protected routes redirect again.
- [ ] Expired/revoked session is rejected on a direct API request.
- [x] Add durable rate limiting for login before public launch.
